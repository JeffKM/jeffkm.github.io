# 02. Figma → Claude Code → Seedance 2.5 로 만드는 스크롤 타임라인 사이트

- **영상**: [Claude Code + Seedance 2.5 = Insane Websites](https://www.youtube.com/watch?v=YUWBku1cNEA)
- **채널**: Kyle Skelly (`@kyleslyf`)
- **한 줄 요약**: Figma에서 디자인을 확정하고 → Dev Mode 프롬프트로 Claude Code에 넘겨 코드로 만들고 → 부족한 이미지·영상은 AI로 생성해 스크롤 연동 타임라인 섹션을 만든다.

## 전체 파이프라인

```
Figma 디자인 확정
   ↓ (JPEG 내보내기 또는 Dev Mode 프롬프트 복사)
Claude Code로 코드 생성 (Fable 5)
   ↓
부족한 에셋을 AI로 생성 (이미지: Nano Banana Pro / GPT image 2, 영상: Seedance 2.5)
   ↓
스크롤 진행률에 영상 재생을 연결
```

## 1단계 — Figma 디자인

- 프레임: MacBook Pro 14, 12 컬럼 그리드.
- 톤: 완전한 검정이 아니라 **약간 초록기가 도는 어두운 톤**. 순수 블랙을 피한다.
- 폰트: 본문 **Geist**(전체 통일), 대형 헤드라인 **Goldman** + `letter-spacing: -10`.
- 클라이언트가 사진 자산을 하나도 갖고 있지 않은 상황 → **모든 이미지를 AI로 생성**해 해결했다.

### 텍스트를 오브젝트 뒤로 보내는 트릭 (Figma 안에서 처리)

1. 헤드라인 텍스트의 투명도를 잠시 낮춰 뒤 이미지를 본다.
2. 텍스트를 가릴 영역(피사체 실루엣)을 쉐이프로 그린다.
3. 텍스트 + 쉐이프를 함께 선택하고 **Subtract**.
4. 그라디언트 + **Progressive Blur**를 얹어 깊이감을 준다.

결과적으로 굴착기 뒤로 헤드라인이 지나가는 레이어감이 만들어진다.

## 2단계 — 디자인을 Claude에 넘기는 두 가지 방법

| 방법 | 절차 | 장단점 |
| --- | --- | --- |
| JPEG 내보내기 | 전체 디자인을 이미지로 저장해 전달 | 무료. 폰트·크기를 **추측**하고, 에셋은 수동으로 내보내야 함 |
| Figma Dev Mode 프롬프트 | 메인 프레임 선택 → Dev Mode → 예시 프롬프트 복사 → Claude Code에 붙여넣기 | 훨씬 빠르고 에셋까지 연결됨. **Figma 유료 플랜 필요** |

모델은 Opus 5도 가능하지만, 더 나은 결과를 위해 **Fable 5**를 선택했다.

첫 빌드 결과 평가: 폭이 Figma와 비슷하게 잡히고 전반적으로 매우 유사하게 나왔다. 보더 스트로크 몇 개가 어긋난 정도의 버그만 남았고, 반응형도 꽤 괜찮게 처리했다. **출발점으로는 충분**하다는 판단.

## 3단계 — 스크롤 연동 타임라인 (핵심 인터랙션)

요청 문장이 그대로 스펙이다.

> 히어로를 100vh로, 빌드 타임라인 섹션도 100vh로. 스크롤 기반 재생으로 **1단계 진행도를 0에서 완료까지** 스크롤에 따라 움직이게. 스크롤 애니메이션이 재생되는 동안 **UI는 sticky로 유지**.

구현된 동작:

- 해당 섹션에 도달하면 화면에 **고정(sticky)** 된다.
- 하단 **진행 바**가 스크롤과 함께 차오른다.
- 그 진행률에 맞춰 영상이 0% → 100%로 재생된다.

## 4단계 — Seedance 2.5 영상 생성

- 최대 **30초**까지 생성 가능. 영상에서는 8초 / 20초를 사용.
- 설정: 16:9, high bit rate, **사운드 off**(웹 배경용이라 불필요).
- 레퍼런스 이미지를 넣고 카메라 무빙을 문장으로 지시한다.
  - 예: "90° 궤도 플라이오버, 흙바닥에서 시작해 콘크리트가 타설되고 벽이 올라간다. 작업자는 등장하지 않고 집이 스스로 지어지는 타임랩스처럼."

### 실패 사례와 교정 — 이 영상에서 가장 값진 부분

처음에는 **4개 단계를 4개의 개별 영상**으로 만들었다. 결과:

- 단계마다 바닥 평면도가 달라지고, 지붕 모양이 바뀌고, 창문이 사라졌다.
- 즉 **연속성이 깨졌다**.

교정한 방법:

> **완성 상태 이미지를 레퍼런스로 주고, 20초짜리 하나의 영상으로 만든다** (5초 × 4단계).
>
> "360° 궤도 플라이오버. 1단계 흙과 기초, 2단계 목조 프레임과 벽·지붕, 3단계 지붕과 인테리어, 4단계 조경. 이 레퍼런스 이미지의 최종 상태와 일치하게. 일관성 유지, 작업자 없음."

**끝 상태를 미리 정해두고 시작하면 일관성이 유지된다.** 이는 워크플로 개선이기도 하다 — 완성 이미지는 어차피 이미 갖고 있기 때문이다.

## 이 포트폴리오에 옮길 수 있는 것

- **sticky 섹션 + 진행 바 + 스크롤 스크럽**은 이 사이트의 "REQUEST → DOMAIN → DATABASE → PROOF" 크롤러 개념과 정확히 맞물린다. 지금은 자동 반복 애니메이션인데, 스크롤 진행률에 물리면 사용자가 흐름을 직접 통제하게 된다.
- **"완성 상태를 먼저 고정한다"**는 원칙은 에셋 생성뿐 아니라 섹션 설계에도 적용된다. 마지막 프레임(=CTA 상태)을 먼저 정하고 역산한다.
- Figma Dev Mode 경로는 유료 플랜이 있을 때만 유효하다. 없다면 스크린샷 + 폰트/색 값 명시가 대안이다.
- 영상 에셋 없이도 진행률 바인딩 자체는 CSS/JS로 구현 가능하다 — 비용 0.
