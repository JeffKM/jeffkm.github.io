# 04. 스크롤로 구동되는 실제 3D 모델 웹사이트

- **영상**: [The NEW Era of 3D Websites is Finally Here.. (It's Insane)](https://www.youtube.com/watch?v=-0zReivPgBM)
- **채널**: Viktor Oddy (`@ViktorOddy`)
- **한 줄 요약**: 03번과 같은 파이프라인이지만, 결과물이 **영상이 아니라 실제 3D 모델**이다. 페이지는 스크롤하지 않고, 스크롤이 씬 전환 애니메이션을 구동한다.

> "이건 영상이 아니다. 실제 3D 모델이다." — 01번(scroll-world)과의 결정적 차이.

## 에셋 파이프라인

```
레퍼런스 이미지 1장 (예: 쿠키)
   ↓ "이 이미지를 앞/뒤/좌/우 4면으로 만들어줘" (GPT image 2 / Nano Banana / Gemini)
4면 이미지를 정렬해 각각 크롭 → PNG/JPEG export
   ↓ multi-view 3D 서비스 → smart topology → generate model
3D 모델 확인 → export GLB (웹용이므로 1K 또는 2K 텍스처)
   ↓ Claude에 드래그 앤 드롭
"three.js로 구현해줘"
```

제작자의 요약: **"이 영상에서 더 볼 게 없다면, 그냥 GLB를 드래그해서 three.js로 구현해달라고 하면 AI가 다 해준다."**

## 인터랙션 설계 — 요청 문장이 곧 스펙

> 웹사이트를 만들어줘. **페이지는 실제로 스크롤되지 않게** 하고, 모든 것을 화면에 **고정(pinned)** 해줘. 스크롤은 씬 1에서 씬 2로 가는 **애니메이션을 구동**하기만 해.
>
> 씬 1은 거대한 굵은 헤드라인 "TASTE THE SKY". 씬 2는 헤드라인 "THE DIFFERENCE". 전환은 스크롤할 때 **헤드라인 글자들이 흩어져 위로 날아가는** 방식.

이것이 이 장르의 표준 구조다.

- 문서 스크롤 = 애니메이션 타임라인 (실제 콘텐츠 이동이 아님)
- 모든 요소는 뷰포트에 고정
- 씬 전환은 문자 단위 분해/재조립 같은 "물리적" 은유

## 레퍼런스 영상을 첨부하는 것이 결정적

> AI는 영상을 아주 잘 이해한다. 원하는 애니메이션의 **영상 예시**가 있다면 그냥 그걸 보내라. 예전에는 이미지만 보낼 수 있었지만 이제는 영상을 보낼 수 있다.

실제로 GLB + 레퍼런스 MP4를 함께 첨부하고 이렇게 요청했다.

> 이 GLB 파일을 사용해서 레퍼런스 영상에 나온 것처럼 웹사이트에서 애니메이션 해줘.

폰트는 **Google Fonts 이름만 알려주면 된다**(Passion One, Inter). 링크가 필요 없다.

## 알려진 함정 — 3D 렌더가 어둡고 탁하게 나온다

Claude로 three.js 씬을 만들면 **모델이 원본보다 어둡게 렌더링되는 문제가 흔하다**. 해결책은 명시적으로 요청하는 것이다.

> **tone mapping을 적용해줘. 없으면 쿠키가 어둡고 탁하게 렌더된다.**

제작자는 이것이 "Claude + 3D의 흔한 문제"라며 색 지시가 담긴 별도 프롬프트를 스크린샷으로 저장해두라고 권한다.

## 모델 선택 기준

| 작업 | 모델 |
| --- | --- |
| 단순 UI 초안, 간단한 수정 | Sonnet 5 / Opus 5 (크레딧 절약) |
| 복잡한 3D 인터랙션, 정밀 애니메이션 | Fable 5 |

"간단한 작업까지 Fable 5를 쓸 필요는 없다"는 판단이 반복적으로 등장한다.

## 결과물 품질에 대한 평가

- 첫 드래프트에서 이미 애니메이션이 동작하고, 텍스트 요소 배치와 sticky 처리까지 붙었다.
- 색감(모델이 레퍼런스보다 어두움)만 후속 보정이 필요했다.
- 제작자 평: "예전에는 에이전시가 몇 달 걸려 만들던 사이트를, 지금은 프롬프트 하나로 만든다."

## 이 포트폴리오에 옮길 수 있는 것

- **"페이지는 고정, 스크롤은 타임라인"** 패턴은 01번의 비디오 스크럽과 동일한 인터랙션 모델이며, 에셋 없이 CSS/JS로도 구현할 수 있다. 이 사이트에 도입한다면 가장 비용 대비 효과가 큰 항목이다.
- **글자 분해 전환(letters scatter and fly off)** — 이 사이트는 이미 `KineticType`으로 대형 타이포를 쓰고 있어, 스크롤 기반 문자 분해 전환과 자연스럽게 결합된다.
- **레퍼런스 영상 첨부** 기법은 앞으로의 작업 방식 자체를 개선한다. 원하는 모션이 있으면 말로 설명하지 말고 영상을 준다.
- three.js + GLB는 번들 크기(수백 KB)와 `output: "export"` 환경에서의 에셋 경로를 고려해야 한다. 도입한다면 히어로 한 곳으로 제한하고 동적 import + `prefers-reduced-motion` 폴백이 필요하다.
