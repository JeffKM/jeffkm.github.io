# 06. 포트폴리오 적용 기록

01~05번 영상에서 뽑은 내용을 이 저장소에 실제로 반영한 결과와, 앞으로 AI 영상 에셋을 붙이는 절차를 적어 둔다.

## 무엇을 바꿨나

기존 홈은 `BUILD` / `VERIFY` 키네틱 타이포 히어로 + 매니페스토 + 케이퍼빌리티 섹션이었다. 이 셋을 없애고 **스크롤 월드** 하나로 대체했다. 히어로라는 개념 자체를 쓰지 않고, 페이지 상단 전체가 스크롤로 재생되는 씬 시퀀스가 되었다.

| 파일 | 역할 |
| --- | --- |
| `lib/scroll-world.ts` | 6개 씬 정의(한·영), 히어로 증거 지표 계산 |
| `components/scroll-world.tsx` | 스크롤 → 씬 진행률 변환, 영상 스크럽, 정적 폴백 |
| `components/scene-layer.tsx` | 영상이 없을 때 쓰는 코드 씬 그래픽 |
| `app/globals.css` | 스크롤 월드 스타일 + 미사용 히어로 CSS 제거(약 6.4KB 감소) |
| `app/[locale]/page.tsx` | 히어로·매니페스토·케이퍼빌리티 → `ScrollWorld` |
| `tests/portfolio.spec.ts` | 첫 씬 완결성 / 스크롤 구동 / 정적 폴백 검증 추가 |

삭제: `components/kinetic-type.tsx` (사용처 없음).

## 씬 구성

브랜드 여정을 시작과 끝만 정하고 채우는 01번 방식을 따랐다.

```
01 출발점  아이디어를 작동하는 흐름으로   ← 헤드라인·맥락·증거·CTA (스크롤 없이 판단 가능)
02 구조    화면 뒤에는 구조가 있다
03 흐름    데이터는 요청에서 증거까지 흐른다
04 실패    실패는 일어난다
05 검증    그래서 직접 검증한다
06 결과    그래서 이렇게 만들었다        ← 아래 작업 섹션으로 착지
```

모든 씬이 같은 중심(월드 코어)을 공유해서, 장면을 갈아타는 것이 아니라 하나의 세계를 계속 통과하는 것처럼 보이게 했다. 01번의 "마지막 프레임 = 다음 첫 프레임" 원칙을 코드 씬으로 옮긴 형태다.

## 인터랙션 모델

`components/scroll-world.tsx`의 동작이다.

1. 트랙 높이 = `씬 수 × 100svh`. 스테이지는 `position: sticky`로 화면에 고정된다.
2. 스크롤 진행률(0~1) → 씬 위치(0~5)로 변환한다.
3. 각 씬은 활성 씬과의 거리(`offset`)에 따라 변형된다.
   - 지나간 씬은 확대되며 사라지고(카메라가 통과), 다가올 씬은 작게 있다가 커진다.
   - `blur`가 거리에 비례해 붙어 심도를 만든다.

### 조정하며 알게 된 것

세 가지는 값을 고치기 전까지 실제로 읽을 수 없는 화면이었다.

- **DWELL (0.32)** — 씬 구간의 앞뒤 32%는 카메라가 멈춰 있고, 가운데 36%에서만 다음 씬으로 넘어간다. 이게 없으면 두 씬이 절반씩 겹친 상태가 스크롤 내내 이어져 헤드라인이 서로를 덮는다.
- **가파른 페이드 (`1 - depth × 1.9`)** — 선형 페이드는 전환 한가운데에서 두 헤드라인을 반반씩 겹쳐 놓는다. 가파르게 떨어뜨리면 전환 순간이 거의 빈 화면이 되고, 한 번에 한 씬만 읽힌다.
- **pointer-events** — 투명해진 씬도 DOM에는 남아 링크 클릭을 가로챈다. 거리 0.5를 넘으면 `pointer-events: none`으로 꺼야 한다. (E2E에서 실제로 클릭이 막혔다.)

추가로 `word-break: keep-all`을 `body`에 넣었다. 대형 타이포에서 한국어가 어절 중간에서 잘렸다.

## 접근성 · 성능

- `prefers-reduced-motion` 또는 모션 정지 버튼(`data-motion="paused"`) → 씬을 세로로 나열한 **일반 문서로 되돌아간다**. 문구는 하나도 사라지지 않는다.
- 스크립트가 없는 환경(`@media (scripting: none)`)에서도 같은 정적 레이아웃이 적용된다.
- 스크롤 핸들러는 `passive` + `requestAnimationFrame`으로 묶었고, 활성 씬에서 1.15칸 이상 떨어진 씬은 그리지 않는다.
- 변형은 `transform` / `opacity` / `filter`만 사용한다.

## 영상 에셋을 붙이는 방법 (아직 안 함)

현재 Higgsfield 계정은 **크레딧 0 / free 플랜**이라 영상을 생성하지 않았다. 대신 씬마다 영상 슬롯을 비워 두었고, 코드 씬이 그 자리를 채우고 있다.

크레딧이 준비되면 이 순서로 진행한다.

1. **씬 이미지 생성** — 01번 문서의 단계적 승인 절차대로 씬 1의 스틸 한 장을 먼저 확인한다. 웹 배경이므로 밝은 톤보다 어두운 톤이 글자를 살린다(01번의 실전 판단).
2. **영상 생성** — 완성 상태를 레퍼런스로 고정하고 카메라 무빙을 지시한다. 단계를 여러 영상으로 쪼개면 일관성이 깨진다(02번의 실패 사례).
3. **씬 연결** — 앞 영상의 마지막 프레임을 FFmpeg으로 뽑아 다음 영상의 시작 이미지로 쓴다. `ffmpeg`은 이미 설치되어 있다.
   ```bash
   ffmpeg -sseof -0.05 -i scene-01.mp4 -vframes 1 scene-02-start.png
   ```
4. **파일 배치** — `public/scroll-world/scene-01.mp4` 형태로 넣는다.
5. **연결** — `lib/scroll-world.ts`의 해당 씬에 `video: "/scroll-world/scene-01.mp4"`를 추가한다. 그 씬은 코드 그래픽 대신 영상 스크럽으로 전환된다. 컴포넌트 수정은 필요 없다.

### 붙이기 전에 확인할 것

- **용량** — GitHub Pages 배포이므로 저장소에 들어간다. 씬당 2~3MB 이하로 인코딩하고(`-crf 30`, 720p), 전체 합을 20MB 아래로 유지하는 편이 안전하다.
- **모바일 데이터** — 6개 영상을 모두 `preload="auto"`로 두면 모바일에서 부담이 크다. 첫 씬만 `auto`, 나머지는 `metadata`로 낮추는 조정이 필요하다.
- **스크럽 성능** — 03번 문서의 지적대로, 영상이 끊기면 MP4 대신 이미지 시퀀스로 바꾸는 선택지가 있다.
- 영상 도입 후에는 `npm run test:e2e`를 다시 돌려 정적 폴백이 유지되는지 확인한다.

## 05번 원칙 적용 결과

| 원칙 | 이전 | 지금 |
| --- | --- | --- |
| 1. 히어로 4요소 | 헤드라인만 있고 CTA·증거 없음 | 첫 씬에 헤드라인 + 맥락 + 증거 지표 4개 + CTA 2개 |
| 2. 위계 | 강함 | 유지 |
| 3. 여백 | 양호 | 유지 |
| 4. 대비 | 고채도 색이 전면에 깔림 | 배경 그래픽을 30% 불투명도로 낮추고 **CTA만 튀게** |
| 5. 소셜 프루프 | 없음 | 첫 화면 CTA 바로 아래(=결정 지점)에 배포/검증 수치 |
| 6. 타이포 | 양호 | `keep-all` 추가로 한국어 줄바꿈 개선 |

증거 지표는 `lib/content.ts`의 실제 프로젝트 기록에서 계산한다. 손으로 관리하는 숫자가 아니므로 콘텐츠가 바뀌면 자동으로 따라간다.

## 발견했지만 고치지 않은 것

다크 모드에서 **lime 배경 위 글자가 밝은 색이 되어 묻히는 문제**가 사이트 전반에 있다. `--kinetic-black`이 다크 테마에서 크림색으로 뒤집히는데, `--kinetic-lime`은 그대로이기 때문이다.

이번에 만든 `.sw-cta`와 `.motion-control`은 글자색을 `#171715`로 고정해 해결했다. 같은 문제가 남아 있는 곳:

- `.kinetic-menu` — 전체 메뉴 오버레이(lime 배경)
- `.kinetic-pill-link` — 작업 섹션 하단의 큰 링크
- `.kinetic-contact > a` — 연락 CTA

라이트 모드에서는 두 값이 같은 색이라 문제가 드러나지 않는다. 고치는 방법은 동일하다(글자색 고정). 이번 작업 범위가 아니라 손대지 않았다.
